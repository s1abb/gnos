Vehicle (Base)
The base Vehicle bound object represents the common vehicle properties and methods that all other vehicle types inherit.

An agent vehicle always implements one of the derived vehicle types (Rail, Road, Generic, Generic Interpolation). See the documentation for derived vehicle variants for more information.

Vehicles are attached to agents within a simulation using the Add Vehicle event node. They can be placed onto a network model at a specific track feature using the Add Vehicle event node or the Place Vehicle event node. Vehicles can be removed from a network model using the Remove Vehicle event node. All vehicles are constructed out of vehicle components. Depending on the type of vehicle different kinds of components can be added which will change the behaviour of the vehicle.

Once a vehicle has been placed on a network model the Move to Location event node can set the vehicles destination and begin it's navigation.

Bound Component Values
All vehicle variants that derive from the base vehicle type implement the following properties and methods to manage the components attached to the vehicle.

Properties
head Component - [get]

The first component of the vehicle.

tail Component - [get]

The last component of the vehicle.

Methods
get_components() []Component

Returns: a list of the vehicle's components.

get_index_of_component(Component) NumberType

Argument 1: The component to find the index for.

Returns: The index for the specified component if it was found, otherwise -1.

get_component_at_index(NumberType) Component

Argument 1: The index for the component to retrieve.

Returns: The component at the specified index, or null if the index is outside the range of allowed values.

set_train(TrainComponent)

Argument 1: The train component used to setup the vehicle.

add_component_to_end(ComponentType|Component)

Argument 1: Type of component to add.

Adds a new component of the specified type to the end of the vehicle's list of components.

add_component_to_start(ComponentType|Component)

Argument 1: Type of component to add.

Adds a new component of the specified type to the start of the vehicle's list of components.

add_components([]ComponentType|Component)

Argument 1: List of components to add to the vehicle.

Adds multiple components to the end of the vehicle's list of components.

add_component_at_index(ComponentType|Component, NumberType)

Argument 1: The type of component to add.

Argument 2: The index to add the component at.

The index must be between 0 and the vehicle's current total number of components.

remove_component(Component)

Argument 1: The component to remove.

remove_all_components()

Removes all components from the vehicle.

distribute_components(Vehicle, NumberType)

Argument 1: Other vehicle to move components to.

Argument 2: Ratio of components to move to the other vehicle. A Number between 0 and 1.

Moves a percentage of components from one vehicle to another. A ratio of 0.5 will move half of the components of a certain type to the other vehicle. e.g. If a vehicle had one component of type A, 2 components of type B and 3 components of type C. Using a ratio of 0.5 will result in moving 1 component of type B and 1 component of type C to the other vehicle.

get_components_filtered(ComponentType) []Component

Argument 1: Type of component to filter by.

Returns: A list of components attached to the vehicle of the specified type.

split(NumberType) []Components

Argument 1: Position to split at.

Splits the train at the position, returns the tail components.

(Deprecated) merge([]Components)

Argument 1: Components to add to end.

Adds instantiated components to tail of train. Deprecated, use add_components method instead

Methods
place(TrackFeature, ?NumberType, ?BoolType) BoolType

Argument 1: The Track feature to place the vehicle at.

Argument 2: (Optional) The offset to from the track feature to place the vehicle at. (Default: 0)

Argument 3: (Optional) Reset the engine state when placing the vehicle. (Default: true)

Returns: true if the vehicle was successfully placed at the specified track feature and offset, otherwise false.

Attempts to place the vehicle at the specified track feature with an optional offset.

clear_destination() BoolType

Returns: true if destinations successfully cleared, otherwise false.

Clears the destination and reservations, setting the destination to its current position.

create_feature(?NumberType, ?BoolType, ?BoolType) TrackFeature

Argument 1: (Optional) Offset from the head of the vehicle to create a track feature.

Argument 2: (Optional) Whether to return a feature with direction reversed, defaults to false.

Argument 3: (Optional) Sets feature prevent_count, defaults to true.

Returns: The newly created Track Feature.

Create a new track feature with an optional offset from the vehicle's head position.

setup_baked_physics_engine(?ListType|BakedPhysicsData|NullType, ?BoolType, ?BoolType) BakedPhysicsData

Argument 1: If null, will instiantiate an empty BakedPhysicsData, otherwise will setup a BakedPhysicsData from the ListType or use the existing BakedPhysicsData if provided.

Argument 2: Use: whether to use the baked physics data to move.

Argument 2: Record: whether to record the average velocity of sections not previously recorded.

Returns: The BakedPhysicsData used by the engine, providing it to another vehicle will share the current data & future recordings.

Wraps the vehicles engine in a baked physics engine. The baked physics engine will use the velocity provided in the BakedPhysicsData to move if Use is true. If record is true it will record the average velocity of sections not previously recorded. The ListType should provide data the same format as BakedPhysicsData.to_list() exports. See Baked Physics. Requires SectionID, Direction and Velocity, and all others are optional, but Velocity can be calculated from Traveled and Duration if provided.

clear_baked_physics_engine() BakedPhysicsData|NullType

Returns: If the vehicle was using a Baked Physics engine it returns the shared baked physics data, otherwise returns null.

Remove the baked physics engine and return the vehicle engine to its underlying type.

flip()

Flips the direction of movement for the vehicle, without changing the order of the components (Equivalent to picking up the vehicle, rotating it 180 degrees, then placing it back on the track).

reverse()

Flips the direction of movement for the vehicle, reversing the order of the components (Equivalent to reversing the order of vehicle components and rotating the vehicle 180 degrees at the same time).

Argument 1: Interval in seconds.

Sets the delay in seconds after a vehicle takes a step.

stop(BoolType?)

Argument 1: (Optional) Reset the engine state (ie speed & rpm becomes 0), defaults to true.

Stops the current run to destination of the vehicle at the end of its next step. For generic interpolation this can be delayed from when it might be expected but will at the longest occur before moving out of a section or when fully moved into one or when it has reached the destination. Optionally pass false in to keep the vehicle speed and other engine state to allow it to continue at speed when run_to_destination is called.

run_to_destination(BoolType?)

Argument 1: (Optional) Come to a stop at the location, defaults to true.

Delays the parent agent until it reaches the target destination. Use set_destination() method prior to calling this.

run_to_destination_charge(NumberType, BoolType?) BoolType

Argument 1: Minimum allowed fuel percentage.

Argument 2: (Optional) Come to a stop at the location, defaults to true.

Returns: true if the vehicle made it to the target destination without going below the minimum allowed fuel threshold, otherwise false.

Same as the run_to_destination method but also specifies a minimum allowed fuel threshold.

Argument 1: Destination feature to calculate distance to.

Argument 2: (Optional) List of passing track features.
